## Objective

by production orchestration until WP54; WP51 writes no `.LST` file.

## Storage Architecture

### VMM Allocations

`listingCaptureInit` requests two 65,535-byte stores. `vmmStoreAlloc` rejects a
zero request and rounds 65,535 to a granted 65,536-byte, 16-page allocation.

1. Metadata store: 4,096 fixed 16-byte records.
2. Emitted-byte mirror: up to 65,536 source-generated bytes.

Both slots are registered immediately. A second-allocation failure leaves the
first centrally owned for fatal cleanup.

### Metadata

- Check count before append.
- Derive offset as record index shifted left four bits.
- Zero-fill and stage one record in shared `CasmVmmBuffer`.
- Transfer exactly 16 bytes.
- Replay through the same record boundary.

### Byte Mirror

Add a dedicated persistent 64-byte stage and one-byte length. On flush, copy the
stage into shared `CasmVmmBuffer`, derive destination as accepted cursor minus
stage length, write one VMM window, and clear length only after success. Finalize
flushes the final partial stage. Byte-at-a-time VMM calls are prohibited.

## Source Capture

Add the WP50-frozen four internal block/line-start bytes and seven-byte public
completed-line sidecar, exactly 11 source BSS bytes total.

### `sourceSetLineCapture`

- `A = 0` disables; nonzero enables.
- Enable clears stale validity and initializes tracking from current traversal.
- Disable clears enable and validity.
- Carry clear; preserve `X/Y`; clobber `A` and flags.
- No VMM or filesystem operation.
- `sourceInit` and `sourceRewind` disable and clear capture.

When enabled, publishing over an unconsumed sidecar raises
`CASM_DIAG_LISTING_REPLAY_MISMATCH`. When disabled, reporting state introduces
no failure path.

Publication covers CR, LF, CRLF, EOF, roots, frames, and synthetic boundaries.
CRLF publishes once. Parent pop reconstructs line start from saved logical
resume offset, so no new frame arrays are added. Synthetic-only separators do
not become metadata records.

### `sourceTakeCompletedLine`

- Pending: carry clear, `A = flags` with `VALID`, fields readable, validity
  consumed.
- None: carry clear, `A = 0`.
- Preserve `X/Y`; no failure, VMM, or filesystem call.

If implementation proves preserving both index registers materially harmful,
stop for amendment rather than silently changing the ABI.

## Listing Module ABI

Add `src/external/casm/listing.s`.

### `listingStateInit`

Clear slots, cursors, flags, stages, transaction, and replay state without
acquiring resources. Call from normal initialization so disabled hooks are
deterministic while `/L` remains rejected. Return carry clear and
`CASM_DIAG_NONE`; clobber `A/X`.

### `listingCaptureInit`

Require initialized/disabled state, allocate both stores, reset capture/replay,
enable source capture only after successful allocation, and commit enabled state
last. Return existing VMM diagnostics on failure; clobber `A/X/Y` and VMM
scratch.

### `listingBeginLine`

No-op when disabled. Otherwise require no active transaction, snapshot PC, byte
cursor, and full flag, then mark active. Duplicate begin raises replay mismatch.

### `listingMirrorByte`

Input `A = source-generated byte`. No-op when disabled. Require active
transaction; reject full before mutation; append/advance/set full; flush each
full 64-byte stage. Return listing-full, replay-mismatch, or VMM-transfer
diagnostics. Clobber `A/X/Y`, flags, and shared VMM scratch.

### `listingCommitLine`

No-op when disabled. Require active transaction and call
`sourceTakeCompletedLine`. No pending or synthetic-only completion clears the
transaction without a record. A physical line computes byte delta, validates
full/wrap state, writes one metadata record, increments count after successful
write, then clears the transaction. Return records-full, replay-mismatch, or
VMM-transfer diagnostics.

### `listingCaptureFinalize`

Require enabled capture, no transaction, and no unconsumed sidecar. Flush final
partial bytes, disable source capture, and mark capture complete. Keep both VMM
allocations for later serialization. Return replay-mismatch or transfer failure.

### Replay

`listingReplayReset` requires complete capture and resets record cursor.
`listingReplayNext` reads one record into `CasmVmmBuffer`, returning
`CASM_STREAM_DATA`, repeat-stable `CASM_STREAM_EOF`, or transfer/replay failure;
advance only after successful read.

## Emitter Integration

In `emitByte`:

1. Preserve input byte on stack.
2. Call existing `emitRawByte`.
3. On failure preserve its diagnostic, discard stacked byte, and return it.
4. Restore byte and call `listingMirrorByte` only when enabled.
5. On mirror failure return before PC increment.
6. Increment PC exactly as before.

PRG acceptance therefore precedes mirror acceptance. Mirror failure follows the
existing incomplete-PRG abort path. Headers and R6 metadata are excluded.

## Pass and Include Integration

- Begin immediately before each Pass 2 `parserParseStatement` when enabled.
- Commit labels, instructions, and ordinary directives after successful
  dispatch.
- Commit parser NEWLINE before looping.
- On EOF commit a pending final physical line but no EOF row.
- Parse/dispatch failure commits nothing.
- In `crpInclude`, complete catalog/event work, commit parent line, then push the
  child. Commit failure prevents push; resolution failure commits nothing.

## Diagnostics

Define/render `$39-$3C`: name collision, records full, bytes full, and replay
mismatch. Reserve `$3D-$41` with contiguity asserts for WP53. Existing VMM
diagnostics remain authoritative.

is a stop condition. Test envelopes are independently measured. No zero-page
growth is allowed.

## Stop Conditions

- More than 11 source BSS bytes, envelope above `$4C00`, frozen-record growth,
  second source buffer, third VMM allocation, or byte-at-a-time mirror writes.
- Metadata over 16 bytes or ambiguous 65,536 endpoint.
- Broken parent-before-child order, Pass 2 source I/O, PRG/relocation/provenance/
  parser change, unacceptable disabled-path regression, or new zero page.

all regressions, measured envelopes, implementation review, user walkthrough,
explicit completion approval, stable `0.1.52`, and synchronized records.
Completion does not activate WP52.
