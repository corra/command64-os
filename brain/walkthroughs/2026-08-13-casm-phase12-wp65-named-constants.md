# CASM Phase 12 WP65 Named Constants Walkthrough

Status: Complete; user-approved 2026-08-14
Branch: `feature/casm-phase12-wp65`
Candidate: CASM `0.2.2` build `1285`, envelope `$3800`-`$9800` (`PRG_SIZE_HEX`
`6000`, bumped from `$5500` per WP64's own recommendation)

## Scope

WP65 implements `identifier = expr` named constant definitions: the lexer's
new `=` token, the parser's `ppsConstant` grammar, the driver's
`crpConstant`, a Pass1→Pass2 constant-resolution sweep with genuine
transitive cycle detection, and the symbol-table/`map.s`/`expr.s` changes
needed to keep labels, constants, and relocation classification consistent
with each other. Full detail (design, scoping decisions, atomic increments)
is in `brain/plans/2026-08-13-casm-phase12-wp65-named-constants.md`.

## Implementation Summary (10 Atomic Increments, all complete)

1. **Symbol record + flags** (`common.inc`): `CASM_SYMBOL_FLAG_CONSTANT`,
   `_RESOLVED`, `_LABEL_DERIVED` added to the existing Flags byte;
   `REF_VMM_LO/HI`, `REF_LEN`, `REF_ADDEND_LO/HI/SIGN`, `REF_EXTRACT` added
   to the record's previously-reserved padding (offsets 37-43 of 64),
   `.assert`-pinned. No record-size change.
2. **`symbolsInsert`/`symbolsLookup` ABI extension** (`symbols.s`): flags no
   longer hardcoded to `DEFINED` — callers set `CasmSymbolInsertFlags`
   explicitly (every existing call site, in `casm.s` and 5 test harnesses,
   updated). `symbolsLookup`'s view gained `CASM_RESOLVE_SYM_FLAGS`,
   surfacing the matched symbol's own kind to callers.
3. **Lexer `=` token**: `CASM_TOKEN_EQUALS`, punctuation table entry,
   diagnostics token-name table entry.
4. **Parser grammar** (`ppsConstant`, `parser.s`): `['<'|'>'] (NUMBER|
   IDENTIFIER) [('+'|'-') NUMBER]`, matching the existing bounded
   expression grammar exactly. A numeric RHS resolves immediately; an
   identifier RHS captures a deferred reference instead of resolving.
5. **`crpConstant` driver** (`casm.s`): Pass 1 only, mirrors `crpLabel`'s
   gate; stages flags and, for a deferred reference, the `Ref*` bookmark,
   into `symbolsInsert`.
6. **Resolution sweep + cycle detection** (`casmResolveConstants`/
   `crcResolveChain`, `casm.s`): runs once at the Pass1→Pass2 boundary.
   Walks each unresolved constant's reference chain via a compact
   absolute-VMM-offset bookmark (new: `CasmSourceResultOffsetLo/Hi`,
   `CasmTokenStartOffsetLo/Hi` — source.s/lexer.s/state.s), a 512-bit
   visited bitmap for cycle detection, and a bounded (`CASM_CONST_CHAIN_MAX
   = 32`) path array to unwind addends from the resolved base back to the
   start. New `symbolsUpdateByIndex` (`symbols.s`) persists each resolved
   node.
7. **`map.s` flags allowlist**: extended from exactly `DEFINED` to also
   accept `DEFINED|CONSTANT|RESOLVED` and its `|LABEL_DERIVED` variant.
8. **`expr.s` relocatable classification**: a resolved constant is
   relocatable only when `LABEL_DERIVED`; a label keeps today's
   unconditional mode-based classification unchanged.
9. **Envelope bump**: `PRG_SIZE_HEX` `$5500`→`$6000` (`CMakeLists.txt`).
10. **`casm_const` test harness**: four real CASM source fixtures
    (`casmconst1-4.seq`, generated by `cmake/GenerateCasmTestFixtures.cmake`,
    packaged on `casm_include_test_d64`) exercised against the real
    `casm.prg` binary under live VICE — not a synthetic unit-test harness.

## Deviations From Plan

Two real deviations, both disclosed to the user in the moment, not
discovered after the fact:

1. **The planned "VMM source-position bookmark" needed new infrastructure,
   not an existing convention.** The plan's Technical Design section
   described this as reusing "the existing bookmark convention used
   elsewhere in `source.s`" — tracing the actual code found no such
   convention: `CasmSourceOffsetLo/Hi` is explicitly a per-span counter,
   reset at every file/include boundary, not a stable position. Building a
   genuinely absolute, permanent offset required new fields
   (`CasmSourceResultOffsetLo/Hi` in `state.s`, computed in
   `source.s`'s `sourceFetchPhysical`; `CasmLookaheadOffsetLo/Hi` and
   `CasmTokenStartOffsetLo/Hi` propagating it through `lexer.s`), mirroring
   the existing FileId/Line/Column provenance-stamping pattern exactly
   rather than inventing new control flow. Flagged to the user as a
   Stop-Conditions-triggering finding before proceeding; user chose to
   build the real infrastructure rather than downgrade to define-before-use.
2. **A real bug found via live VICE testing, not code review**:
   `ppsConstant`'s addend handling (both the numeric and identifier RHS
   paths) called `exprParseAddend` but never issued the follow-up
   `lexerNext` needed to advance past the addend's own `NUMBER` token on
   the sign-present path — `exprParseNumeric`'s "token remains current"
   contract, the same step `expr.s`'s own `consumeIdentifier` takes right
   after its equivalent call. First assembly attempt of `casmconst1.s`
   failed `EXPECTED NEWLINE` at exactly the addend token. Fixed in both
   paths, matching `expr.s`'s own pattern; re-verified live afterward.
3. **Two live-testing fixture-authoring mistakes, not product bugs**: the
   original `casmconst2.s`/`casmconst3.s` fixtures used `A`, `B`, and `X` as
   constant names, colliding with `CASM_TOKEN_REGISTER` (single-letter
   `A`/`X`/`Y` lex as the accumulator/index-register operand form, not
   `CASM_TOKEN_IDENTIFIER`) — `A = B` produced `SYNTAX ERROR`, never
   reaching `ppsLabel`/`ppsConstant` at all. Renamed to `FOO`/`BAR`/`SELF`,
   no product code change, re-verified.
