## What changed

`src/external/casm/diagnostics.s` — `diagPrintSourceContext` now prints the
`IN FILE <name>` line for **every** diagnostic that has a valid recorded
source location (`CasmDiagLocValid != 0`), regardless of `CasmSourceCount`
or include depth. The old WP35/WP48 gate
(`lda CasmSourceCount / cmp #2 / bcc @skipFileName`, plus the `bmi
@printFileName` frame shortcut and the two now-dead labels) is deleted;
the unused `.import CasmSourceCount` is removed. Non-located diagnostics
(CLI/option, file-service, internal) still gate out at the
`CasmDiagLocValid` check above and print the message line alone.

Net: a pure deletion. `casm.prg` = 25,853 code bytes (unchanged from the
pre-bump build), within the `$7400` MAIN envelope.

## Increment 1 — characterization (no code change)

10 all-uppercase `.seq` fixtures on a scratch disk (`casm_phase15_test.d64`
copy + `cc1541 -f "<n>.s" -T SEQ -w`). Ran 5 cases live under VICE 3.10
against **CASM 0.6.1 b1417**, screen-RAM decoded. Same located diagnostic
throughout: `CASM: OPERAND OUT OF RANGE` from `LDA #300`.

| Case | `IN FILE`? (before) |
| --- | --- |
| (a) single root, no include, error in root | **NO** |
| (b) single root that `.INCLUDE`s, error **in root** | **NO** |
| (c) error in the `.INCLUDE`d file | YES `diagci.s` + `INCLUDED FROM diagcr.s LINE 2 COLUMN 1` |
| (d) two CLI roots, error in 2nd | YES `diagd2.s` |
| (e) nested root→A→B, error in B | YES `diageb.s` + 2 `INCLUDED FROM` lines |

**Conclusion: the gap is 3a (suppression), not 3b (provenance mis-stamp).**
In (a)/(b) the stamped `CasmDiagLocFileId` is the root's and is correct —
the name is withheld purely by the `CasmSourceCount < 2` gate. No
provenance fix needed.
